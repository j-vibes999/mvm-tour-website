# คู่มือ URL และการเผยแพร่ MVM Group

โค้ดที่แก้ไขอยู่ใน `dist/` ส่วน `build/` คือเว็บไซต์พร้อมเผยแพร่ที่สร้างจากเนื้อหาล่าสุด อย่าแก้ไฟล์ใน `build/` โดยตรง เพราะการ build ครั้งถัดไปจะสร้างใหม่ทั้งหมด

## สร้างและเปิดดู

จากโฟลเดอร์โครงการ เรียก:

```sh
npm ci
npm run build
npm run dev
```

`npm run dev` สร้าง build ใหม่และเปิด local preview อัตโนมัติ โดยฟังเฉพาะ `127.0.0.1` เปิด `http://127.0.0.1:4173/th/` สำหรับภาษาไทย หรือ `/en/` สำหรับภาษาอังกฤษ หลังแก้เนื้อหา รูป หรือโค้ด ให้สั่ง build แล้วรีเฟรชหน้า หากใช้คำสั่ง `npm run build` และ `npm run dev` ให้ดูค่าปัจจุบันใน `package.json`

## กำหนดโดเมนจริงก่อนเผยแพร่

ตัวสร้างเว็บเลือกโดเมนตามลำดับนี้:

1. ตัวแปรแวดล้อม `SITE_URL`
2. ค่า `site.url` ใน `dist/content.js` ถ้ามี
3. URL ที่มีอยู่เดิมใน `og:url` ของ `dist/index.html` ซึ่งขณะจัดทำคู่มือนี้คือ `https://lao-travel-discovery.fitfrog1.chatgpt.site/`

ไม่เดาโดเมนใหม่ให้บริษัท หากโดเมนจริงเปลี่ยน ให้ build ใหม่ด้วยค่าใหม่ เช่น คำสั่งต่อไปนี้เป็นเพียงตัวอย่างรูปแบบ ต้องแทนด้วยโดเมนที่บริษัทใช้จริง:

```sh
SITE_URL='https://YOUR-REAL-DOMAIN/' node scripts/build-static.mjs
```

เว็บไซต์นี้ออกแบบให้วางที่รากโดเมน (`/`) ไม่ใช่โฟลเดอร์ย่อย `/travel/` ตัวสร้างจะปฏิเสธ URL ที่มีโฟลเดอร์ย่อยหรือข้อมูลผู้ใช้/รหัสผ่าน เพื่อป้องกันการสร้างลิงก์ผิด

เผยแพร่ **ไฟล์ทั้งหมดภายใน `build/`** ไปยังรากเว็บไซต์ ไม่ต้องตั้งกฎให้ทุก URL ย้อนกลับไปยังหน้าแรก เพราะทุกหน้ามีไฟล์ HTML ของตัวเองอยู่แล้ว หากผู้ให้บริการรองรับ ให้ใช้ `404.html` เป็นหน้าเมื่อไม่พบ URL และส่งสถานะ HTTP 404

## โครงสร้างลิงก์

| หน้า | ตัวอย่าง |
|---|---|
| ภาษาไทย / อังกฤษ | `/th/` และ `/en/` |
| สำรวจลาว | `/th/explore/` |
| ภูมิภาค | `/th/explore/north/` |
| แขวง | `/th/province/luang-prabang/` |
| สถานที่ | `/th/province/luang-prabang/kuang-si/` |
| แพ็กเกจ | `/th/package/luang-prabang-discovery/` |
| รายการแพ็กเกจตามแขวง | `/th/packages/?province=luang-prabang` |
| คำถามที่พบบ่อย | `/th/faq/` |
| เก็บสถานที่ | `/th/saved/` |
| เตรียมสอบถาม | `/th/inquiry/?kind=place&ref=luang-prabang%2Fkuang-si` |

เปลี่ยน `th` เป็น `en` เพื่อใช้ภาษาอังกฤษ ปุ่มเปลี่ยนภาษาจะคงสถานที่และตัวกรองเดิมไว้ ลิงก์แบบเก่า `#/province/...` ยังคงรองรับเพื่อรักษาลิงก์ที่เคยส่งให้ลูกค้า

## สิ่งที่ตัวสร้างเตรียมให้

- HTML ที่อ่านชื่อสถานที่ คำอธิบาย รายการเที่ยว และลิงก์ต่อได้แม้ไม่เปิด JavaScript ส่วนแผนที่ การปัดภาพ การเก็บสถานที่ และแบบฟอร์มยังต้องใช้ JavaScript
- ชื่อหน้า คำอธิบาย canonical และภาพแชร์ของแต่ละสถานที่/แพ็กเกจ
- `hreflang` ภาษาไทย ลาว อังกฤษ และจีน พร้อม `sitemap.xml` และ `robots.txt`
- ข้อมูลองค์กรแบบ JSON-LD ใช้เฉพาะชื่อและช่องทางติดต่อที่กรอกไว้จริง ไม่เพิ่มเบอร์โทร ที่อยู่ หรือใบรับรองสมมุติ
- หน้า `/saved/` และ `/inquiry/` เป็น `noindex,follow` และไม่อยู่ใน sitemap เพราะข้อมูลเป็นของผู้ใช้แต่ละคน ตัวกรองและพารามิเตอร์สอบถามไม่ถูกเพิ่มเข้า canonical

หลังเผยแพร่โดเมนจริงแล้ว ให้ตรวจเปิดลิงก์สถานที่โดยตรง รีเฟรชหน้า เปลี่ยนภาษา และลองแชร์ลิงก์ ภาพตัวอย่างบนแพลตฟอร์มแชทอาจใช้แคชเดิมชั่วคราว ส่วนการปรากฏในผลค้นหาขึ้นกับการเก็บข้อมูลของระบบค้นหา ไม่ได้เกิดขึ้นทันทีหลัง build


## ไฟล์พร้อมเผยแพร่และ cache

การ build ใช้ esbuild ที่ติดตั้งด้วย `npm ci` เพื่อรวม JavaScript เป็น ESM พร้อม chunk ที่แยกโหลดตามการใช้งานจริง รวมถึง catalog ของภาษาที่เลือกซึ่งอ้างอิงไฟล์ hash ของ release เดียวกัน ไฟล์ใน `assets/js/` และ `assets/css/` มี hash อยู่ในชื่อไฟล์ โดย HTML อ้างถึงไฟล์ของ release นั้นโดยตรง ส่วน `asset-manifest.json` แสดง entry, stylesheet และกราฟโมดูลที่ preload ตอนเริ่มต้น

ไฟล์ `content.js`, `i18n.js`, `viewer-gestures.js` และ URL ภาษา `locales/lo.js` / `locales/zh.js` ที่ URL เดิมเป็น bridge ไปยังโมดูลชุดเดียวกับแอป เพื่อให้ integration ที่ import URL เดิมใช้สถานะข้อมูลร่วมกันได้ **ห้ามตั้ง immutable cache ให้ bridge หรือรูปและฟอนต์ที่ชื่อไม่มี hash**

| กลุ่ม URL | นโยบายที่เตรียมใน `_headers` |
|---|---|
| `/assets/js/*`, `/assets/css/*` | `public, max-age=31536000, immutable` เพราะชื่อมี hash |
| HTML แต่ละภาษา, bridge JS, catalog loader, manifest, sitemap, robots | `public, max-age=0, must-revalidate` |
| `/assets/images/*`, `/assets/fonts/*` | revalidate เพราะชื่อเดิมอาจถูกแทนด้วยไฟล์ใหม่ |

`build/_headers` เป็น config สำหรับโฮสต์ที่รองรับรูปแบบ `_headers` เท่านั้น ไม่ได้หมายความว่าโฮสต์จริงอ่านไฟล์นี้แล้ว ถ้าใช้โฮสต์อื่น ให้นำ path และ header แต่ละรายการไปตั้งในระบบของผู้ให้บริการ และตรวจ response หลังเผยแพร่จริงว่าได้ค่าตามตาราง อย่าตั้ง immutable ครอบทั้ง `/assets/*`

เผยแพร่แบบ atomic release: อัปโหลดไฟล์ hash ใหม่ให้ครบก่อนสลับ HTML และเก็บไฟล์ hash ของ release ก่อนหน้าไว้ระยะหนึ่งสำหรับแท็บหรือ HTML เก่าที่ยังเปิดอยู่ อย่าลบไฟล์เก่าทันทีระหว่าง deploy และอย่าแก้ไฟล์ใน `build/` หลัง build เพราะชื่อ hash, preload, CSP และไฟล์บีบอัดจะไม่สอดคล้องกัน ให้แก้ `dist/` แล้ว build ใหม่

CSS ยังคงเป็น stylesheet เดียวตามลำดับ cascade เดิม เพื่อให้การเปลี่ยนหน้าในแอปทันทีไม่มีช่วงที่สไตล์ของหน้าถัดไปยังไม่พร้อม ไฟล์ CSS ต้นฉบับที่ไม่ได้ถูกเรียกโดย HTML จะไม่ถูกคัดลอกไปใน build แล้ว

## Compression

ตัวสร้างเตรียมไฟล์ `.gz` และ `.br` ข้าง HTML, JS, CSS, JSON, XML, SVG และไฟล์ข้อความ โดยไม่บีบอัด WebP/PNG/JPEG/WOFF2 ซ้ำ ไฟล์ต้นฉบับยังอยู่สำหรับไคลเอนต์ที่ไม่ส่ง `Accept-Encoding`

โฮสต์ต้องเลือก sidecar ตาม `Accept-Encoding`, ส่ง `Content-Encoding: br` หรือ `gzip`, คง `Content-Type` ของไฟล์ต้นฉบับ และส่ง `Vary: Accept-Encoding` ผู้ให้บริการบางรายบีบอัดที่ CDN เองและไม่ใช้ sidecar ซึ่งใช้ได้เช่นกัน **อย่าตั้งให้ทุกคำขอรับ `.br` เสมอ** และอย่า rewrite URL ในหน้าไปยัง `.gz`/`.br`

local preview ใช้ `Cache-Control: no-store` และส่งไฟล์ต้นฉบับเพื่อให้เห็นการแก้ไขทันที จึงไม่ใช้วัดประสิทธิภาพ cache หรือ compression ของโฮสต์จริง ตรวจที่โดเมนที่บริษัทเลือกหลังเผยแพร่ เช่น:

```sh
curl -I 'https://YOUR-REAL-DOMAIN/en/'
curl -I -H 'Accept-Encoding: br, gzip' 'https://YOUR-REAL-DOMAIN/en/'
```

แทนตัวอย่างโดเมนด้วยค่าที่อนุมัติแล้ว และตรวจ hashed JS/CSS จาก `asset-manifest.json` เพิ่มด้วย

## Security headers และตรวจ release

`_headers` เตรียม `nosniff`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`, Permissions Policy ที่ปิด camera/microphone/geolocation และ Content Security Policy สำหรับเว็บนี้ CSP อนุญาตสคริปต์จาก origin เดียวกันและ hash ของ inline boot scripts ที่สร้างจริง โดยไม่อนุญาต inline event handlers ส่วน inline style ยังคงจำเป็นสำหรับตำแหน่งภาพ สี และการเคลื่อนไหว จึงอนุญาตเฉพาะด้าน style ไว้อย่างชัดเจน ไม่มีการเพิ่มบุคคลที่สามให้รันสคริปต์

ก่อนเปิดใช้ CSP บนโฮสต์จริง ให้ลองเป็น `Content-Security-Policy-Report-Only` หรือทดสอบ release ที่ใช้ header จริงให้ครบทั้งสี่ภาษา การเปิดสถานที่โดยตรง การเปลี่ยนภาษา การโหลดรูป การปิด viewer การเตรียมและดาวน์โหลดข้อความสอบถาม และ fallback เมื่อโหลดแอปไม่สำเร็จ แล้วจึงใช้ policy แบบบังคับหลังตรวจว่าไม่มีการบล็อกฟังก์ชันที่จำเป็น การแก้ข้อความ inline script ต้อง build ใหม่เพื่อสร้าง hash ใหม่

HTTPS, redirect จาก HTTP, HTTP/2 หรือ HTTP/3 และ HSTS เป็นการตั้งค่าของโฮสต์/โดเมนจริง คู่มือนี้ไม่สมมุติว่าการตั้งค่าเหล่านั้นทำแล้ว ตั้ง HSTS เฉพาะเมื่อโดเมนและ subdomain ที่เกี่ยวข้องพร้อมใช้ HTTPS; ไม่เพิ่ม `includeSubDomains` หรือ preload โดยไม่มีการตรวจโดเมนจริง

หลังสลับ release ตรวจ URL ที่มีและไม่มี trailing slash, หน้าไม่มีอยู่ต้องได้ HTTP 404, canonical/hreflang/sitemap ต้องชี้โดเมนที่อนุมัติ และผู้ใช้ที่มี cache เก่าต้องเปิด release ใหม่ได้ครบ การทดสอบเฉพาะ `127.0.0.1` ไม่ยืนยันค่า CDN และ security headers ที่ production
