# คู่มือแก้ไขเนื้อหาเว็บไซต์ MVM Group

ข้อมูลสถานที่ แพ็กเกจ และบริษัทอยู่ใน `dist/content.js` ส่วนรายการที่คัดไว้แสดงหน้าแรกอยู่ใน `dist/home-discovery.js`
แก้ไฟล์นี้ด้วยโปรแกรมแก้ข้อความทั่วไป (เช่น VS Code) แล้วบันทึก จากนั้นสร้างไฟล์เว็บตามข้อ 9 เพื่อดูผล รวมทั้งอัปเดตหน้าที่ค้นหาเจอและภาพแชร์

เว็บไซต์รองรับไทย ลาว อังกฤษ และจีนตัวย่อ ข้อความต้นฉบับยังเขียนแบบ `{ th: 'ข้อความภาษาไทย', en: 'English text' }` ส่วนคำแปลลาวและจีนอยู่ใน `dist/locales/` โดยใช้ข้อความอังกฤษเดิมเป็นคีย์ และค่าเป็น `[ภาษาลาว, ภาษาจีนตัวย่อ]` เมื่อเพิ่มข้อความใหม่ต้องเพิ่มคำแปลให้ครบก่อน build ระบบจะแจ้งข้อผิดพลาดแทนการแสดงภาษาอื่นปะปน

- `places.js`: ชื่อแขวง เมือง สถานที่ ประเภท และคำบรรยาย
- `details.js`: รายละเอียด เวลา การเดินทาง และข้อควรรู้
- `programs.js`: โปรแกรมรายวัน FAQ บริษัท และข้อมูลหน้าแรก
- `ui.js`: เมนู ปุ่ม แบบฟอร์ม สถานะ และข้อความระบบ ตัวแทนค่า เช่น `{0}` และ `<br>` ต้องคงให้ตรงต้นฉบับ
- ข้อมูลบริษัทจริงที่เพิ่มภายหลังสามารถระบุ `lo` และ `zh` ในออบเจ็กต์นั้นโดยตรงได้ ควรแปลให้ครบทั้ง 4 ภาษา
- ราคาทุกภาษายังเป็นบาทไทย ไม่ใช่การแปลงสกุลเงิน และคงป้ายราคาตัวอย่างไว้

ดูคำศัพท์และแหล่งตรวจชื่อเฉพาะใน `docs/i18n-language-review-2026-10-20.md` แล้วรัน `npm test`, `npm run check` และ `npm run test:browser` หลังเปลี่ยนคำแปล

ปุ่มภาษาในส่วนหัวเปิด dropdown เดียว มีไทย ลาว อังกฤษ และจีน เมื่อเข้าผ่าน URL หลัก `/` ระบบใช้ภาษาที่ลูกค้าเลือกไว้ก่อน ถ้ายังไม่เคยเลือกจะอ่านภาษาที่ต้องการจากเบราว์เซอร์ตามลำดับ และใช้ภาษาอังกฤษเมื่อไม่มีภาษาที่รองรับ การเลือกเองจะบันทึกใน `localStorage` ชื่อ `mvm-language` ส่วน URL ที่ระบุภาษา เช่น `/lo/packages/` จะเปิดตามลิงก์นั้นเสมอ รายละเอียดพฤติกรรมและผลตรวจอยู่ใน `docs/language-picker-2026-10-21.md`

## 1. ข้อมูลติดต่อ (ควรทำก่อนเปิดเว็บจริง)

อยู่ด้านบนสุดของไฟล์ ในส่วน `site.contact`

```js
contact: {
  line: '@mvmgroup',                 // LINE ID
  whatsapp: '8562012345678',         // ตัวเลขล้วน มีรหัสประเทศ 856
  phone: '+856 20 1234 5678',
  email: 'hello@mvmgroup.la',
  facebook: 'https://www.facebook.com/mvmgroup',
  address: { th: 'ที่อยู่ภาษาไทย', en: 'Address in English' },
},
```

- ถ้ายังเว้นว่าง ช่องทางนั้นยังใช้ส่งคำถามถึงบริษัทไม่ได้ ไม่ควรนำข้อมูลตัวอย่างด้านบนไปใช้จริง
- เมื่อใส่ค่าแล้ว ปุ่มแชท LINE, WhatsApp, โทร, อีเมล และ Facebook จะลิงก์ไปยังช่องทางจริงทันที
- เมื่อใส่ `line` แล้ว จะมีปุ่ม LINE สีเขียวลอยอยู่มุมขวาล่างของทุกหน้า ยกเว้นหน้าวางแผนทริป (ซึ่งมีช่องทางส่งให้เลือกอยู่แล้ว) และขณะดูสถานที่เต็มจอ หลังลูกค้าเลื่อนดูหน้าแล้วประมาณ 6 วินาที ปุ่มจะทักทายสั้น ๆ ว่า "ສະບາຍດີ!" หนึ่งครั้งต่อการเข้าชม ลูกค้าปิดได้และจะไม่ขึ้นซ้ำในการเข้าชมนั้น ถ้า `line` ว่าง ปุ่มนี้จะไม่ปรากฏเลย
- กรอกอย่างน้อยหนึ่งช่องทางจริงและทดสอบจากโทรศัพท์ก่อนนำเว็บไปประชาสัมพันธ์ เว็บไซต์ไม่ส่งรายการสถานที่หรือข้อความสอบถามถึงบริษัทเอง ลูกค้าต้องเลือกส่งผ่านช่องทางติดต่อ

## 2. แพ็กเกจทัวร์ (`packages`)

```js
{
  id: 'luang-prabang-discovery',      // ชื่อเฉพาะภาษาอังกฤษ ห้ามซ้ำ ใช้เป็นลิงก์ของหน้า
  provinceId: 'luang-prabang',        // แขวงของทริป (ดูรายชื่อ id ในข้อ 3)
  destinationId: 'luang-prabang',     // จุดหมายของแพ็กเกจ แยกหนองเขียว/เมืองงอยได้แม้อยู่แขวงเดียวกัน
  destination: { th: 'หลวงพระบาง', en: 'Luang Prabang' }, // หัวข้อหลักบนการ์ดและหน้ารายละเอียด
  photo: 'wat-xieng-thong',           // ภาพถ่ายพร้อมเครดิตจาก photos; หรือใช้ image สำหรับภาพของเว็บเอง
  title: { th: '...', en: '...' },
  days: 3, nights: 2,
  price: 5900,                        // ตัวเลขตัวอย่าง บาทต่อท่าน
  priceStatus: 'example',             // คงป้ายตัวอย่างไว้จนกว่าจะมีราคาจริงและเงื่อนไขครบ
  currency: 'THB',
  highlights: { th: ['...', '...'], en: ['...', '...'] },
  suitability: { th: ['เหมาะกับใคร'], en: ['Who this plan may suit'] },
  activityLevel: { th: 'ลักษณะการเดิน/กิจกรรม', en: 'Walking and activity considerations' },
  itineraryStatus: 'suggestion',
  itinerary: [
    {
      day: 1,
      title: { th: 'หัวข้อวันแรก', en: 'Day one title' },
      summary: { th: 'แผนที่เสนอ ไม่ใช่ตารางยืนยัน', en: 'A suggested plan, not a confirmed schedule' },
      activities: { th: ['กิจกรรมแรก', 'กิจกรรมถัดไป'], en: ['First activity', 'Next activity'] },
      stops: ['luang-prabang/wat-xieng-thong'],
    },
    // เพิ่มให้ครบจำนวน days
  ],
  routeStops: ['luang-prabang/wat-xieng-thong'], // รวม stops ทุกวันตามลำดับ ตัดค่าซ้ำ
},
```

แพ็กเกจที่เพิ่มจะขึ้นในหน้า "แพ็กเกจทัวร์" และในหน้าของแขวงนั้นจะมีปุ่ม "ดูแพ็กเกจ" ให้อัตโนมัติ
หน้าราคาแสดงการ์ดเรียงข้างกัน 3 คอลัมน์บนคอมพิวเตอร์ 2 คอลัมน์บนแท็บเล็ต และ 1 คอลัมน์บนมือถือ การ์ดแสดงรูป ชื่อจุดหมาย จำนวนวัน และราคา กดเปิดจึงอ่านไฮไลต์และโปรแกรมละเอียดได้ โดยเรียงนครหลวงเวียงจันทน์ 2,900 บาท (2 วัน 1 คืน), วังเวียง 4,900 บาท, หลวงพระบาง 5,900 บาท, หนองเขียว 6,500 บาท และเมืองงอย 6,900 บาท (สี่รายการหลัง 3 วัน 2 คืน) ตามด้วยจำปาสัก 8,900 บาท (4 วัน 3 คืน) ทั้งหมดเป็น **ราคาตัวอย่างต่อท่าน** ตามที่เจ้าของอนุญาต ยังไม่ใช่ข้อเสนอขายหรือการยืนยันการจอง

- `priceBasis` อธิบายหน่วยราคาและสิ่งที่ยังไม่ได้กำหนด ไม่เขียนว่า "รวมทุกอย่าง" เมื่อยังไม่มีรายการยืนยัน
- `itineraryNote` ระบุว่าแผนรายวันเป็นข้อเสนอแนะ ต้องตรวจเวลาเดินทาง เวลาเปิด และสภาพอากาศก่อนจัดทริป
- `quoteDetails.confirmed` หมายถึงข้อมูลที่แสดงในหน้าเว็บ เช่น ระยะเวลาแผนตัวอย่างและราคาแสดง ไม่ใช่การยืนยันว่ารวมรถหรือที่พัก
- `quoteDetails.toConfirm` คือรายการที่ต้องตกลงในใบเสนอราคา ได้แก่ วันและจำนวนคน จุดรับ–ส่ง รถ/ตั๋ว ที่พัก อาหาร ค่าเข้าชม กิจกรรม ผู้ดูแล ราคาสุทธิ และเงื่อนไขการชำระ/เปลี่ยนแปลง
- `itinerary` ต้องมีวันเรียง 1 จนถึง `days` และ `stops` ทุกค่าต้องตรงกับสถานที่ที่มีอยู่จริงใน `provinces`
- `routeStops` ใช้ทำแถบภาพ "สถานที่ในเส้นทางนี้" ในหน้ารายละเอียด (แสดงเมื่อมีตั้งแต่ 2 แห่ง) และใช้จับคู่ "โปรแกรมที่ตรงกับรายการของคุณ" ในหน้าที่อยากไป จึงควรใส่ทุกสถานที่ที่โปรแกรมพาไปจริงตามลำดับ
- `activities` แสดงกิจกรรมเป็นรายการอ่านง่ายใต้คำอธิบายแต่ละวัน ต้องใส่ไทยและอังกฤษ หากโปรแกรมเดิมยังไม่มี ระบบแสดงรายชื่อสถานที่ของวันนั้นแทน
- ห้ามใช้ `image` อ้างคีย์ที่มีเฉพาะใน `photos` เช่น `nong-khiaw` และ `muang-ngoi` ให้ใช้ `photo` เพื่อให้รูปและเครดิตแสดงถูกต้อง
- ถ้าจะเปิดขายจริง ให้เจ้าของบริษัทตรวจเส้นทางและราคาพร้อมรายการรวม/ไม่รวมก่อน การเปลี่ยนตัวเลขอย่างเดียวไม่ทำให้ข้อมูลตัวอย่างกลายเป็นเงื่อนไขขายที่ครบ

## 3. แขวงและสถานที่เที่ยว (`provinces`)

มีครบ 18 แขวง เรียงจากเหนือลงใต้ id ของแต่ละแขวง:

| ภาค | id |
|---|---|
| ลาวเหนือ | `phongsaly` `luang-namtha` `oudomxay` `bokeo` `luang-prabang` `houaphanh` `xayaboury` `xiengkhouang` `xaisomboun` |
| ลาวกลาง | `vientiane-capital` `vientiane-province` `bolikhamxay` `khammouane` `savannakhet` |
| ลาวใต้ | `salavan` `sekong` `champasak` `attapeu` |

ห้ามเปลี่ยน id ของแขวง เพราะใช้จับคู่กับรูปแผนที่

สถานที่แต่ละแห่งเขียนด้วยคำสั่ง `p(...)` ตามลำดับนี้

```js
p('kuang-si', 'waterfall', 'น้ำตกตาดกวางสี', 'Kuang Si Falls',
  'คำอธิบายภาษาไทย 1–2 ประโยค', 'English description', { photo: 'kuang-si' }),
//  id         ประเภท       ชื่อไทย           ชื่ออังกฤษ        ...                           รูป (ไม่ใส่ก็ได้)
// รูป: photo: '...' = ภาพจากรายการ photos (Wikimedia) หรือ image: '...' = รูปในโฟลเดอร์ assets/images
```

- ในหน้าแขวง สถานที่ทั้งหมดจะเรียงเป็นการ์ดรูปที่เลื่อนไปทางซ้าย–ขวาได้ แตะการ์ดแล้วจะเปิดหน้าดูรายละเอียดเต็มจอ ซึ่งปัดหรือกดลูกศรไปดูที่ถัดไปของแขวงเดียวกันได้ ลิงก์ของแต่ละที่ เช่น `/th/province/luang-prabang/kuang-si/` ภาษาอังกฤษเปลี่ยน `/th/` เป็น `/en/` ส่งลิงก์จากแถบที่อยู่ของเบราว์เซอร์ให้ลูกค้าได้เลย
- สถานที่ที่ยังไม่มีรูป จะแสดงรูปทรงของแขวงพร้อมไอคอนตามประเภทแทน เมื่อมีรูปแล้วค่อยใส่ `photo` หรือ `image`
- ประเภทที่ใช้ได้: `nature` ธรรมชาติ, `waterfall` น้ำตก, `cave` ถ้ำ, `temple` วัดและพระธาตุ, `history` ประวัติศาสตร์, `culture` วัฒนธรรม, `activity` กิจกรรม, `viewpoint` จุดชมวิว, `market` ตลาด
- ลำดับในรายการคือลำดับเลข 01, 02, 03 บนหน้าเว็บ
- `tags` ของแขวง (ป้าย "เหมาะกับ") ใช้ได้: `nature` `culture` `history` `adventure` `relax`
- ถ้าเขียน "ๆ" ให้เขียนแบบเดียวกับในไฟล์ คือ `'...ต่าง' + NB + 'ๆ ...'` เพื่อไม่ให้ "ๆ" ตกไปขึ้นบรรทัดใหม่

## 4. ที่เที่ยวยอดนิยม (ข้อมูลในหน้าดูรายละเอียด)

สถานที่ที่มีข้อมูลใน `placeDetails` จะแสดงคำอธิบายเต็ม จุดเด่น และข้อมูลที่ควรรู้ในหน้าดูรายละเอียดเต็มจอ และขึ้นในหน้า "ที่เที่ยวยอดนิยม" ตามลำดับที่เขียนไว้
สถานที่ที่ยังไม่มีข้อมูลส่วนนี้ก็เปิดดูได้ แต่จะแสดงเฉพาะคำอธิบายสั้นจากข้อมูลแขวง
(ลิงก์เก่าแบบ `#/place/แขวง/สถานที่` ยังใช้ได้ ระบบจะพาไปหน้าดูรายละเอียดให้เอง)

```js
'luang-prabang/kuang-si': {
  about: { th: 'คำอธิบาย 2–3 ประโยค', en: '...' },
  highlights: { th: ['จุดเด่น 1', 'จุดเด่น 2', 'จุดเด่น 3'], en: ['...', '...', '...'] },
  best: { th: 'ช่วงเวลาที่ดี', en: '...' },
  time: { th: 'ควรใช้เวลา', en: '...' },
  access: { th: 'การเดินทาง', en: '...' },
  note: { th: 'น่ารู้ (ไม่ใส่ก็ได้)', en: '...' },
  tip: { th: '...', en: '...', lo: '...', zh: '...' }, // เคล็ดลับจากทีมงาน (ไม่ใส่ก็ได้)
},
```

- สถานที่นั้นต้องมีรูป (`photo: '...'` หรือ `image: '...'`) ในข้อมูลแขวงด้วย
- `tip` คือคำแนะนำสั้น ๆ จากทีมงานที่เคยไปจริง จะแสดงเป็นกล่อง "เคล็ดลับจากทีมงาน" ในหน้าดูสถานที่เต็มจอและหน้าที่ค้นหาเจอ ต้องใส่ครบ `th`, `en`, `lo` และ `zh` ในออบเจ็กต์เดียวกัน (`npm test` จะแจ้งถ้าขาดภาษาใด) ห้ามแต่งเคล็ดลับที่ทีมไม่ได้ยืนยัน ถ้าไม่ใส่ กล่องนี้จะไม่ปรากฏ
- ตัวเลือก "ไปเดือนไหนดี?" ในหน้าสำรวจลาวใช้เฉพาะช่วงเดือนที่เขียนไว้ใน `best` อยู่แล้ว ถ้าต้องการให้สถานที่ใดขึ้นในเดือนที่เหมาะ ให้ระบุช่วงเดือนในข้อความ `best` ก่อน แล้วเพิ่มเลขเดือน (1–12) ใน `recommendedMonths` ของ `dist/discovery.js` ตอนนี้มีข้อมูล 12 แห่ง และเดือน พ.ค.–ก.ค. ยังไม่มีสถานที่แนะนำ
- `mustSee` เก็บรายการสถานที่เด่นเดิมไว้ ส่วนหน้าแรกปัจจุบันคัดเมือง รูปแบบการเที่ยว และเรื่องราวใน `dist/home-discovery.js` และมีลิงก์ไปหน้าที่เที่ยวยอดนิยมทั้งหมด

## 5. หน้าแรก

- `slides` ภาพหน้าแรก 14 ภาพ ปัจจุบันเป็นภาพถ่ายจริงทั้งหมด ใช้ `photo` อ้างคีย์ในแค็ตตาล็อกภาพ หากมี `placeRef` ต้องเป็นสถานที่ที่มีอยู่ในแขวงของ `provinceId` เพื่อให้ปุ่มสำรวจเปิดจุดหมายได้ตรงภาพ แก้ `name`, `line` และ `alt` ให้ครบสองภาษา เครดิตจะเชื่อมไปยังภาพที่กำลังแสดงโดยอัตโนมัติ
- สไลด์เริ่มเล่นทุก 8 วินาทีบนการตั้งค่าปกติ ปุ่มใช้สัญลักษณ์เล่น/หยุดเท่านั้น สามารถปัดแถบภาพบนมือถือหรือลากด้วยเมาส์ได้ การชี้เมาส์บนภาพไม่หยุดการเล่น เมื่อเปลี่ยนเป็นโหมดลดการเคลื่อนไหวหรือใช้คีย์บอร์ดสำรวจ สไลด์หยุดจนกว่าจะกดเล่นเอง
- `homeDestinations` ใน `dist/home-discovery.js`: เวียงจันทน์ วังเวียง หลวงพระบาง หนองเขียว และเมืองงอย พร้อมช่องสำรวจทั้งหมดรวมเป็นกริด 6 ช่อง หนองเขียวและเมืองงอยเชื่อมหน้าสถานที่ตรงตัว
- `homeStyles`: ตัวเลือกเที่ยว 4 แบบ ลิงก์ไปตัวกรองเดิมในหน้าสำรวจลาว หมวดริมน้ำใช้คำค้น "แม่น้ำ" ร่วมกับประเภท `nature`
- `homeMoments`: เรื่องราวจากภาพจริง 3 ชุด แก้ชื่อและคำบรรยายให้ตรงภาพ พร้อม `href` หน้าสถานที่ และคีย์ `photo` ที่มีเครดิต
- `homeTripIds`: รหัสโปรแกรมตัวอย่างที่คัดมาแสดง 3 ใบ หน้าแรกไม่มีราคา หน้าแพ็กเกจยังแสดงครบทุกโปรแกรม
- `steps`: ขั้นตอนเลือกสถานที่ เตรียมรายละเอียด และสอบถามเพื่อตรวจใบเสนอราคา แสดงรวมกับส่วน MVM Group แบบกระชับ
- `featured` และ `valueProps` ยังเก็บเป็นข้อมูลเดิม แต่ไม่ได้ควบคุมกริดเมืองและแถบแนะนำบนหน้าแรกใหม่
- หน้าแรกจะแสดงทีมจริงสูงสุด 2 คนและรีวิวจริงรายการแรก เมื่อเติม `companyProfile.ownerData.team` และ `reviews` ใน `dist/content.js` แล้ว หากยังว่าง ส่วนนี้จะไม่ปรากฏ

## 5.1. เกี่ยวกับบริษัทและคำถามที่พบบ่อย

`companyProfile` อยู่ถัดจาก `site` ด้านบนของไฟล์ ประกอบด้วยหัวข้อ `title` คำอธิบาย `intro` และแนวทาง `approach`
ตอนนี้ข้อมูลที่เจ้าของแจ้งและยืนยันแล้วคือชื่อ **MVM Group** จึงยังไม่มีการแต่งปีที่ก่อตั้ง สมาชิกทีม จำนวนรถ หรือรีวิว

ข้อมูลจริงที่ควรเติมใน `companyProfile.ownerData`:

| ช่อง | ข้อมูลที่ต้องเตรียม |
|---|---|
| `legalName` | ชื่อนิติบุคคลที่ใช้จริง |
| `registration` | ข้อมูลทะเบียนบริษัทที่ต้องการเผยแพร่ |
| `tourLicence` | เลข/รายละเอียดใบอนุญาตที่เกี่ยวข้องและยืนยันแล้ว |
| `officeAddress` | ที่อยู่สำนักงานภาษาไทยและอังกฤษ |
| `serviceAreas` | พื้นที่ที่บริษัทรับจัดทริปจริง แยกไทย/อังกฤษ |
| `welcome` | ข้อความต้อนรับสั้น ๆ จากเจ้าของหรือทีมงาน ชื่อ ตำแหน่ง และรูป (ไม่ใส่ก็ได้) แสดงเป็นการ์ดทักทาย "ສະບາຍດີ" บนหน้าแรกและหน้าเกี่ยวกับเราเมื่อมีข้อความของภาษานั้น ใส่ครบ 4 ภาษาทุกช่อง (ดู `docs/copy-update-2026-10-22.md`) |
| `team` | ชื่อ ตำแหน่ง และรูปทีมจริงที่ได้รับอนุญาตให้ใช้ |
| `fleet` | ประเภทรถ รายละเอียด และภาพรถที่ใช้ให้บริการจริง |
| `reviews` | ชื่อและข้อความรีวิวจริงพร้อม `sourceUrl` ที่ตรวจสอบได้และได้รับอนุญาต |

ช่องที่ยังไม่มีข้อมูลให้คง `''` หรือ `[]` ไว้ ไม่ใส่บัญชีโทรศัพท์ ภาพบุคคล หรือรีวิวตัวอย่างให้ดูเหมือนข้อมูลจริง
รูปทีมและรถใช้ฟิลด์ `image` อ้างชื่อไฟล์ใน `images` เช่นเดียวกับรูปอื่นของเว็บ

`faq` เป็นรายการ `{ id, question: { th, en }, answer: { th, en } }` ปัจจุบันอธิบายการสำรวจ สถานที่ที่เก็บไว้ ราคาตัวอย่าง การเตรียมข้อมูลสอบถาม และการไม่มีระบบชำระเงินออนไลน์
แก้คำตอบให้ตรงกับพฤติกรรมของเว็บและบริการจริงเสมอ ไม่เพิ่มคำรับประกันเวลาตอบกลับ บริการ หรือเงื่อนไขที่บริษัทยังไม่ได้ตกลง

## 6. ภาพถ่ายสถานที่ (Wikimedia Commons)

ภาพชุดเดิมของสถานที่ยอดนิยมอยู่ในรายการ `photos` ใน `dist/content.js` ส่วนภาพที่เติมใหม่และรายการจับคู่ภาพของแต่ละแขวง/สถานที่อยู่ใน `dist/media-catalog.js`
ทั้งสองชุดเป็นภาพจริงจาก Wikimedia Commons ที่ต้องใช้ตามสัญญาอนุญาตของภาพนั้นและให้เครดิตผู้ถ่าย
เว็บแสดงเครดิตให้อัตโนมัติบนภาพในหน้าดูรายละเอียด และรวมไว้ในหน้า "เครดิตภาพ" (`/th/credits/`) ห้ามลบชื่อผู้ถ่ายหรือสัญญาอนุญาตออก

- `extraPhotos` ใน `media-catalog.js` เก็บไฟล์ต้นทาง ผู้ถ่าย สัญญาอนุญาต และ `sourceUrl` ของภาพที่เพิ่ม
- `provincePhotos` จับคู่ id แขวงกับภาพที่ใช้เป็นภาพเปิด ภาพนี้อธิบายแขวงโดยรวม ไม่ได้หมายความว่าเป็นภาพทุกสถานที่ในแขวง
- `placePhotos` จับคู่ `'id-แขวง/id-สถานที่'` กับภาพของสถานที่นั้นโดยตรง ไม่ใช้รูปสถานที่ใกล้เคียงมาแทนโดยไม่ระบุ
- สร้างไฟล์ภาพในเว็บและอัปเดต `localPhotos` ด้วย `node scripts/cache-photos.mjs` แล้วสร้างเว็บใหม่ โปรแกรมนี้ต้องเชื่อมต่ออินเทอร์เน็ต มี `cwebp` และ `ffprobe` และคงเครดิต/รายละเอียดการปรับขนาดไว้ รายละเอียดอยู่ใน `docs/media-guide-th.md`
- อย่าแก้บล็อก `BEGIN GENERATED LOCAL PHOTOS` ด้วยมือ หากเปลี่ยนต้นทางภาพให้เรียกคำสั่งจัดเตรียมภาพใหม่
- ถ้าจะเปลี่ยนเป็นรูปของบริษัทเอง: ใส่รูปตามข้อ 7 แล้วเปลี่ยน `photo: 'kuang-si'` ของสถานที่นั้นเป็น `image: 'ชื่อรูป'` และนำรายการ `placePhotos` ของสถานที่นั้นออกถ้ามี

## 7. รูปภาพของเว็บเอง

รูปอยู่ที่ `dist/assets/images/` แต่ละรูปมี 3 ขนาด เป็นไฟล์ WebP

- `ชื่อรูป-1600.webp` กว้าง 1600 px สำหรับจอใหญ่
- `ชื่อรูป-800.webp` กว้าง 800 px สำหรับมือถือ
- `ชื่อรูป-160.webp` ขนาด 160×120 px สำหรับรูปย่อ

เพิ่มรูปใหม่แล้วต้องลงชื่อและขนาดจริงของรูปไว้ใน `images` ด้วย เช่น `'vat-phou': { w: 1600, h: 1000 }`
หากสถานที่ยังไม่มีภาพที่ยืนยันได้ หน้าเว็บจะแสดงรูปทรงของแขวงบนพื้นสีเขียวแทน เมื่อมีรูปแล้วให้ใส่ `image: 'ชื่อรูป'` ในข้อมูลสถานที่
ภาพเปิดแขวงในชุดปัจจุบันมีการจับคู่ไว้ใน `provincePhotos` ถ้าจะใช้ภาพของบริษัทแทน ต้องนำรายการจับคู่ของแขวงนั้นออกด้วยเพื่อไม่ให้ภาพเดิมยังถูกเลือกก่อน

## 8. แผนที่

ขอบเขตแขวงในไฟล์ `dist/map-data.js` มาจาก geoBoundaries ซึ่งใช้ข้อมูล OpenStreetMap (สัญญาอนุญาต ODbL)
ต้องคงข้อความ "© OpenStreetMap contributors" ไว้ใต้แผนที่ในหน้าสำรวจลาว ไม่ต้องแก้ไฟล์นี้

## 9. ตรวจก่อนอัปโหลด

ในโฟลเดอร์โปรเจกต์ สั่ง:

```
npm test        # ตรวจว่าข้อมูลครบและลิงก์ระหว่างข้อมูลถูกต้อง
npm run check   # ตรวจว่าไม่มีไฟล์ JavaScript พิมพ์ผิด
node scripts/build-static.mjs  # สร้างหน้า HTML และข้อมูลแชร์จากเนื้อหาปัจจุบัน
npm run dev     # เปิดดูเว็บในเครื่องตาม URL ที่คำสั่งแสดง
```

`dist` เป็นไฟล์ต้นฉบับ ส่วนไฟล์ที่สร้างพร้อมขึ้นเว็บอยู่ใน `build` ต้องสร้างใหม่หลังแก้เนื้อหา แล้วอัปโหลดทั้งโฟลเดอร์ `build` เพื่อให้เส้นทางหน้าย่อยเปิดได้โดยตรง
ลิงก์เก่า `#/province/...` ยังรองรับและเปลี่ยนเป็นเส้นทางใหม่อัตโนมัติ

ก่อนเผยแพร่ให้กำหนดโดเมนจริงผ่าน `site.url` หรือ environment variable `SITE_URL` ของคำสั่งสร้างเว็บ เพื่อให้ canonical, แผนผังเว็บ และภาพแชร์ชี้ไปยังโดเมนที่ใช้จริง
